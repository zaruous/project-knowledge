# Project Status

1. Read `AGENTS.md` and `CLAUDE.md`.
2. Prefer `wiki/`, `entities/`, `data/manifests/`, and approved test/release records.
3. Separate confirmed state from missing or uncertain evidence.
4. Report open requirements, implementation gaps, missing tests, unresolved defects, and material risks when present.
5. Cite repository paths and stable IDs in the summary.
6. Do not treat `llm/generated/` as approved project state.
